# Навантажувальне тестування

## Інструмент і сценарій
- k6, скрипт `loadtest/script.js`.
- 3 етапи (розгін, стале навантаження, спад), загалом 10 хвилин, до 80 віртуальних користувачів.
- Сценарій: створення позиції (201), список, вибірка за категорією, читання позиції.
- Поріг: `p(95) < 1000 мс`, `http_req_failed < 1%`.

## Результати

| Метрика | A (без кешу) | B (з кешем) |
|---|---|---|
| Запитів | 2114 | 5569 |
| Запитів/с | 1,82 | 9,26 |
| Медіана | 2,49 с | 0,50 с |
| p90 | 7,99 с | 30,97 с |
| p95 | 8,78 с | 32,59 с |
| p99 | 12,7 с | 58,11 с |
| Помилки | 0% | 2,26% (126, timeout) |
| Ітерацій завершено | 179 (80 перервано) | 549 (31 перервано) |

Тривалість A склала ~19 хв (замість 10) через дуже повільні відповіді.

## Спостереження
- Поріг p95 < 1 с не виконано в обох прогонах. Це результат експерименту, а не помилка скрипта: сервіс на 0,25 vCPU перевантажується.
- У B між 6:57 і 7:50 лічильник завершених ітерацій майже не змінювався (~430), потім з'явилися `request timeout`. Схоже на тимчасовий затор (нові задачі ще не готові, насичення CPU або з'єднань з БД).
- Тест створює записи, тож база перед B була більшою, ніж перед A. Це трохи ускладнює пряме порівняння.
