# Кешування (Redis)

## Реалізація
- ElastiCache Redis (`inventory-redis`), створений через Terraform.
- Застосунок: cache-aside (`app/cache.py`): читання спершу з Redis, при промаху з БД із записом у кеш.
- Змінні середовища задачі: `CACHE_ENABLED` (керується Terraform `cache_enabled`), `CACHE_TTL=30`, `REDIS_URL`.
- Прогін A: `cache_enabled=false`. Прогін B: `cache_enabled=true`.

## Порівняння (80 VUs, 10 хв)

| Метрика | A (без кешу) | B (з кешем) |
|---|---|---|
| Запитів/с | 1,82 | 9,26 |
| Медіана | 2,49 с | 0,50 с |
| p95 | 8,78 с | 32,59 с |
| Помилки | 0% | 2,26% |


## Висновок
Пропускна здатність зросла приблизно в 5 разів, а медіанна затримка впала з 2,49 до 0,50 с, тобто типові запити стали значно швидшими. Але хвіст гірший: p95 вищий, з'явилися таймаути (2,26%). Імовірні причини: короткий TTL (30 с), записи під час тесту інвалідують кеш, слабка задача (0,25 vCPU), прогрів нових задач під час масштабування. Твердження про вплив кешу підтверджуються лише після заповнення частки влучань вище; якщо CacheHits близько нуля, покращення зумовлене чимось іншим і це треба вказати.
